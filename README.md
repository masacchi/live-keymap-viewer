# Live Keymap Viewer

Vial キーボード(まずは Cornix LP)の **押しているキー** と **いまのレイヤー** を、
リアルタイムに表示する Windows 向けのデスクトップアプリ。

- キーマップ・レイヤー・物理配置は**キーボードから読む**。アプリに固定データは無い
- Windows を日本語(JIS)キーボード設定のまま使っている前提で、**実際に入力される文字**を出す
  (Vial / Pipette は US 配列前提の表示なので、JIS だとずれる)。US 表記にも切り替えられる
- 通常ウィンドウと、**常に最前面のクリック透過オーバーレイ**を切り替えられる
- Vial でキーマップを変えたら、このアプリに戻るだけで反映される

---

## 使う

GitHub のリリース(または Actions の実行結果の Artifacts)から、どちらかを取ってくる(Windows x64 向け):

- **インストーラー**(`…-win-x64-setup.exe`)… 実行するとスタートメニューに入る。管理者権限は要らない
- **ポータブル版**(`…-win-x64-portable.zip`)… 展開した `LiveKeymapViewer/` の中の `LiveKeymapViewer.exe` を実行する

署名していないので、初回は SmartScreen の警告が出る(「詳細情報」→「実行」)。
ビルドの流れは [docs/DEVELOPMENT.md §5](docs/DEVELOPMENT.md#5-windows-に置く)。

手元で作って Windows に置くなら(WSL):

```bash
npm install
npm run deploy:win
```

Windows のデスクトップに `LiveKeymapViewer/` ができるので、中の `LiveKeymapViewer.exe` を実行する。
**フォルダごと**でないと動かない(exe だけを持ち出すと起動しない)。

実機が無くても、画面の **「モックで試す」** で動きを確かめられる。モックでは図のキーを
クリックすると押したままになり、もう一度で離す(アンロックは色の付いた 2 つを押したままにして 10 秒ほど)。

## 使い方

### 1. 接続する

「キーボードに接続」で Cornix を選ぶ。一度選んだキーボードには、次の起動から自動で繋がる。
使っている途中で USB を抜き差ししたり、PC がスリープから戻ったりしたときも、自動で繋ぎ直す
(「切断」を押したあとは繋ぎ直さない)。

### 2. アンロックする

押しているキーを読むには Vial のアンロックが要る(ファームがキーロガー対策で止めている)。
ロックされていれば**自動で手順が始まる**ので、案内に出るキー(Cornix なら `Tab` と `Q`。図では
白い破線が回っている)を、バーが埋まるまで同時に押し続ける(5 秒ほど。離すとやり直し)。
押しても図は光らないが、バーが進んでいれば効いている。キーボードを挿し直すまで解除されたまま。

### 3. 画面の見方

| 表示 | 意味 |
|---|---|
| 黄色いキー | いま押している |
| **レイヤー色で塗られ `L2` と出るキー** | そのキーを長押しして L2 を出している最中 |
| 図全体の**色付きの縁** | ベース以外のレイヤーが出ている(色はツールバーの `L2` と同じ) |
| 一段明るいキー | 記号キー |
| キー下端の色帯 `L2` | 長押しすると L2 が出るキー(名前を付けていれば `L2 記号`) |
| 薄いキー | 透過(KC_TRNS)。下のレイヤーの値を出している |
| 主文字の上の小さな文字 | Shift を押したときに出る文字 |
| **Shift を押しているあいだ明るくなるキー** | Shift で入る文字が変わるキー。Shift 側の文字が大きく出る |
| 図の下の `↺ 音量− ↻ 音量+` | ノブの割り当て(表示中のレイヤーのもの) |
| ツールバーの `L0` `L1 BS 長押し` … | レイヤーの一覧と、そのレイヤーへの行き方。図に出しているレイヤーは塗られて輪が付き、ほかに有効なレイヤーは薄く塗られる。中身の無いレイヤーは `+5 空` に畳まれる |
| ツールバーの `Ctrl` `Shift` `Alt` `Win` | いま効いているモディファイアが白く点く(MT の長押しが確定したときも) |
| 図全体の縁が**破線** | プレビュー中(下記)。実際のレイヤーではない。縁の上に札が出る |

### レイヤーの一覧・プレビュー・名前

- ツールバーの `L0 L1 …` に**ポインタを乗せる**と、そのレイヤーを図に出す(**プレビュー**)。
  レイヤーキーを押さえ続けなくても中身を見られる。そのレイヤーに入るキー(L2 なら Space)は
  レイヤーの色で縁取られる。外せば戻る
- **押すとプレビューのまま固定**する。キーを押すか Esc、札の「戻る」で実際の表示に戻る
- **名前を付けられる**(例: `L2 記号`)。ツールバー右の「設定」から、またはレイヤーをダブルクリック。
  ツールバーやキーの色帯(`L2 記号`)にも出る。空にすると消える。名前はキーボードごとに覚える

### 記号の出し方

ツールバーの「@ 記号の出し方」を開くと、記号ごとのカードが並ぶ。カードには、記号と、それを出す
キーの組み合わせ(例: `@` → `Space 長押し` + `W`)が出る。2 番目に手数の少ない打ち方があれば
「または」で添える。

カードを押すと、そのレイヤーを図に出し、押すキー(Shift も)を黄色い枠で光らせる。縁の上の札にも
「@ は Space 長押し + W」と出る。キーを押すか Esc で戻る。

### 設定

ツールバー右の「設定」から:

- **レイヤー名**
- **ノブの割り当て** … 図の上に並べるか、下に並べるか
- **長押しまで** … この時間(100〜500ms、既定 200ms)押し続けたら LT のレイヤーが出たと見なす。
  キーボードの設定(tapping term / hold timeout)と合わせる。ずれると表示だけ早く / 遅く切り替わる
- **オーバーレイ** … 濃さ・「L0 のあいだは薄くする」と薄くしたときの濃さ・後ろのぼかし(オーバーレイに入らなくても変えられる)
- **許可したキーボード** … 起動したときに自動で繋ぐキーボード。「忘れる」と、次からは選び直す

### 4. キーマップを変えたとき

Vial で編集したあと、このアプリのウィンドウに戻れば**自動で読み直す**。
ツールバー左のデバイス名を押して「キーマップを読み直す」でも更新できる。

物理配置やカスタムキーの名前(定義)は、繋ぐたびに読まずに覚えておく。ファームを焼き直したのに
図や名前が古いままなら「キーマップを読み直す」を押す(こちらは定義も読み直す)。

Vial を開いたままでも動くようにしてあるが、確実なのは Vial を閉じてから使うこと。

### 5. オーバーレイ

`Ctrl+Alt+K` で通常ウィンドウ ⇄ オーバーレイ。オーバーレイ中はクリックが下のウィンドウに抜ける。

左上の小さな操作パネル(ふだんは `⠿ L2` だけ。ポインタを乗せると広がる)から:

- **⠿ をドラッグ** … 移動
- **濃さ** … 透明度(20〜100%)
- **L0 で薄く** … ベースレイヤーのあいだは図を薄くし、ほかのレイヤーに入るか Shift を押すと濃く戻す(既定で有効)。
  横の **残す** で、薄くしたときの濃さ(0〜80%、既定 20%)を選ぶ
- **後ろをぼかす** … オーバーレイの後ろの画面をすりガラスのようにぼかす(Windows 11 のみ、既定は切)。
  ぼかしの強さは OS が決める。薄くしているあいだは外す
- **通常ウィンドウに戻す**

右下のつまみでサイズを変えられる。位置・サイズ・濃さ・薄くしたときの濃さ・ぼかしは次回も引き継ぐ
(ツールバーの「設定」からも変えられる)。

### 6. JIS / US

ツールバーのトグルで切り替える。JIS では `KC_QUOTE` が `:`、`KC_LBRACKET` が `@` のように、
Windows が JIS として扱ったときに実際に入る文字を出す。

## できないこと

- **ノブを回したときの表示。** 押し込みは光るが、回転は Vial / VIA のプロトコルで取れない
- **Bluetooth はまだ使えない想定**(USB は確認済み)。BT の遅さへの対応が要る → [docs/BLUETOOTH.md](docs/BLUETOOTH.md)
- Combo / Key Override / One Shot / TT の厳密な再現
- 対応は Vial protocol 6 / VIA protocol 9 のみ

詳しくは [docs/STATUS.md](docs/STATUS.md)。

## 接続の確認状況

| 接続 | 状態 |
|---|---|
| USB | ✅ 2026-09-20、Windows + Cornix LP で動作 |
| Bluetooth | 🔶 OS レベルでは Vial が答える(往復 約 450ms)が、アプリはまだ対応していない。選択ダイアログでは「不明なデバイス(E118:0001)」と出る([docs/BLUETOOTH.md](docs/BLUETOOTH.md)) |

USB と Bluetooth の両方で繋がっていても大丈夫。Windows には同じキーボードが 2 つ見えるが、
実際に答える方(両方答えるなら速い USB)を自動で選ぶ。

WSL 上で起動した場合は、USB でもキーボードは見えない(WSL2 に USB が無いため)。
実機は Windows 側で使う。
