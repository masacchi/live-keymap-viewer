# Live Keymap Viewer

<img src="assets/icon.svg" width="96" height="96" alt="">

Vialキーボード(まずはCornix LP)の**押しているキー**と**いまのレイヤー**を、リアルタイムに表示する
Windows向けのデスクトップアプリです。

- キーマップ・レイヤー・物理配置は**キーボードから読みます**。アプリにキーボードごとのデータは持ちません
- Windowsを日本語(JIS)キーボードの設定のまま使っている前提で、**実際に入力される文字**を表示します
  (VialやPipetteはUS配列の前提で表示するので、JISだとずれます)。US表記にも切り替えられます
- 通常のウィンドウと、**常に最前面に出るクリック透過のオーバーレイ**を切り替えられます
- Vialでキーマップを変えたら、このアプリで読み直すだけで反映されます

---

## インストール

[GitHubのリリース](https://github.com/masacchi/live-keymap-viewer/releases)から、どちらかをダウンロードします
(Windows x64向け)。

| 種類 | ファイル | 説明 |
|---|---|---|
| インストーラー | `live-keymap-viewer-win-Setup.exe` | 実行するとそのままインストールして起動します。管理者権限は要りません。新しい版が出たら、アプリの中から更新できます |
| ポータブル版 | `…-win-x64-portable.exe` | 8MBほどのexe 1つで動きます。自動では更新しません |

- インストール先は`%LOCALAPPDATA%\live-keymap-viewer`です。スタートメニューとデスクトップにショートカットができます
- 設定とログは`%APPDATA%\live-keymap-viewer`に置きます
- 画面はWindowsの**WebView2**で表示します。Windows 11には最初から入っています(無ければインストーラーが先に入れます)
- 署名していないので、初回はSmartScreenの警告が出ます。「詳細情報」→「実行」で進めてください
- 開発中の版は`dev-build`というプレリリースに置いています。「Live Keymap Viewer Dev」という別のアプリとして入り、
  リリース版と並べて使えます(設定も別です)。開発版は開発版どうしで更新し、リリース版には移りません

### 更新

インストーラーで入れた場合は、新しい版が出ると設定ボタンに印が付きます。
「設定」→「このアプリ」→「更新して再起動」で更新できます。

### 試してみる

実機が無くても、画面の「**モックで試す**」で動きを確認できます。モックでは図のキーをクリックすると
押したままになり、もう一度クリックすると離します(アンロックは、白い破線が回っている2つのキーを
押したままにして10秒ほど待ちます)。

## 使い方

### 1. 接続する

「キーボードに接続」を押してCornixを選びます。一度選んだキーボードには、次の起動から自動で接続します。
使っている途中でUSBを抜き差ししたり、PCがスリープから戻ったりしたときも、自動で接続し直します
(「切断」を押したあとは接続し直しません)。

### 2. アンロックする

押しているキーを読むには、Vialのアンロックが必要です(キーロガー対策として、ファームが止めています)。
ロックされていれば**自動で手順が始まります**。案内に出るキー(Cornixなら`Tab`と`Q`。図では
白い破線が回っています)を、バーが埋まるまで同時に押し続けてください(Cornixなら、押せばすぐに終わります。
5秒ほどかかるキーボードもあり、その場合は途中で離すとやり直しです)。
押しても図は光りませんが、バーが進んでいれば押せています。キーボードを挿し直すまで、アンロックは続きます。

### 3. 画面の見方

| 表示 | 意味 |
|---|---|
| 黄色いキー | いま押しているキー |
| **レイヤーの色で塗られ、`L2`と出るキー** | そのキーを長押しして、L2を出している最中 |
| 図全体の**色付きの縁** | ベース以外のレイヤーが出ている(色はツールバーの`L2`と同じ) |
| 一段明るいキー | 記号キー |
| キーの下端の色帯`L2` | 長押しするとL2が出るキー(名前を付けていれば`L2記号`) |
| 薄いキー | 透過(KC_TRNS)。下のレイヤーの値を表示している |
| 主文字の上の小さな文字 | Shiftを押したときに出る文字 |
| **Shiftを押しているあいだ明るくなるキー** | Shiftで入る文字が変わるキー。Shift側の文字が大きく出る |
| 円いキーと、その上下の`↻ 音量+` `↺ 音量−` | ノブ(円いキーは押し込み)。上が右に回したとき、下が左に回したときの割り当て(表示中のレイヤーのもの) |
| ツールバーの`L0` `L1` … | レイヤーの一覧。図に出しているレイヤーは塗られて輪が付き、ほかに有効なレイヤーは薄く塗られる。中身の無いレイヤーは`+5空き`にまとめられる |
| ツールバーの`Ctrl` `Shift` `Alt` `Win` | いま効いているモディファイアが白く点く(MTの長押しが確定したときも) |
| 図全体の縁が**破線** | プレビュー中(下記)。実際のレイヤーではない。縁の上にラベルが出る |

### 4. レイヤーの一覧・プレビュー・名前

- ツールバーの`L0 L1 …`に**ポインタを乗せる**と、そのレイヤーを図に表示します(**プレビュー**)。
  レイヤーキーを押さえ続けなくても中身を見られます。そのレイヤーに入るキー(L2ならSpace)は、
  レイヤーの色で縁取られます。ポインタを外すと戻ります
- **クリックするとプレビューのまま固定**します。キーを押すか、Escか、ラベルの「戻る」で実際の表示に戻ります
- **名前を付けられます**(例: `L2記号`)。ツールバー右の「設定」から付けるか、レイヤーをダブルクリックします。
  名前はツールバーやキーの色帯にも出ます。空にすると消えます。名前はキーボードごとに保存されます
- 一覧にポインタを乗せると、そのレイヤーへの行き方(`Space長押し`など)がツールチップに出ます。
  設定の「レイヤーの行き方を添える」をオンにすると、番号の横にも並びます

### 5. 記号の出し方

ツールバーの「@ 記号の出し方」を開くと、記号ごとのカードが並びます。カードには、記号と、それを出す
キーの組み合わせ(例: `@` → `Space長押し` + `W`)が出ます。次に手数の少ない打ち方があれば、
「または」で添えます。

カードをクリックすると、そのレイヤーを図に表示し、押すキー(Shiftも)を黄色い枠で光らせます。
縁の上のラベルにも「@ は Space長押し + W」と出ます。キーを押すかEscで戻ります。

### 6. 設定

ツールバー右の「設定」から変えられます。

- **レイヤー名**
- **ツールバー** … レイヤーの行き方を番号の横に添えるか
- **長押しまで** … この時間(100〜500ms、既定200ms)押し続けたら、LTのレイヤーが出たとみなします。
  キーボードの設定(tapping term / hold timeout)と合わせてください。ずれると、表示だけ早く / 遅く切り替わります
- **オーバーレイ** … 濃さ、「ベースレイヤー(L0)のあいだは薄くする」と薄くしたときの濃さ、後ろの画面のぼかし(オーバーレイに入らなくても変えられます)
- **許可したキーボード** … 起動したときに自動で接続するキーボード。「忘れる」を押すと、次からは選び直しになります
- **このアプリ** … 版、ログを開く、更新

### 7. キーマップを変えたとき

Vialで編集したあとは、ツールバー左のデバイス名を押して「キーマップを読み直す」を選びます
(自動では読み直しません。Bluetoothでは1回に30秒以上かかるためです)。

物理配置やカスタムキーの名前(キーボードの定義)は、接続のたびに読まずに保存しておいたものを使います。
ファームを書き換えたのに図や名前が古いままなら、同じく「キーマップを読み直す」を選んでください
(定義も読み直します)。

Vialを開いたままでも動くようにしてありますが、Vialを閉じてから使うのが確実です。

### 8. オーバーレイ

`Ctrl+Alt+K`で、通常のウィンドウとオーバーレイを切り替えます。オーバーレイでは、クリックが下のウィンドウに抜けます。

左上の小さな操作パネル(ふだんは`⠿ L2`だけ。ポインタを乗せると広がります)でできること:

- **⠿をドラッグ** … 移動
- **濃さ** … 不透明度(20〜100%)
- **L0で薄く** … ベースレイヤーのあいだは図を薄くし、ほかのレイヤーに入るかShiftを押すと濃く戻します(既定でオン)。
  横の「L0の濃さ」で、薄くしたときの濃さ(0〜80%、既定20%)を選べます
- **後ろをぼかす** … オーバーレイの後ろの画面を、すりガラスのようにぼかします(Windows 11のみ、既定はオフ)。
  ぼかしの強さはOSが決めます。薄くしているあいだは外れます
- **通常ウィンドウに戻す**

右下のつまみで大きさを変えられます。位置・大きさ・濃さ・薄くしたときの濃さ・ぼかしは、次回も引き継ぎます
(ツールバーの「設定」からも変えられます)。

### 9. JISとUS

ツールバーの切り替えで選びます。JISでは`KC_QUOTE`が`:`、`KC_LBRACKET`が`@`のように、
WindowsがJISとして扱ったときに実際に入る文字を表示します。

## できないこと

- **ノブを回したことの表示。** 押し込みは光りますが、回転はVial / VIAのプロトコルでは取れません
- **Bluetoothでの利用は、まだ実機で確かめていません**(USBは確認済み)。Bluetoothの遅さに合わせて待つ時間を
  延ばすようにしてありますが、選択画面で名前が出ないなどの課題が残っています → [docs/BLUETOOTH.md](docs/BLUETOOTH.md)
- Combo / Key Override / One Shot / TTの厳密な再現
- 対応はVial protocol 6 / VIA protocol 9だけです

詳しくは[docs/STATUS.md](docs/STATUS.md)にあります。

## 接続の確認状況

| 接続 | 状態 |
|---|---|
| USB | ✅ WindowsとCornix LPで動作を確認 |
| Bluetooth | 🔶 OSからはVialが応答する(往復は約450ms)。アプリは遅さに合わせて待つようにしたが、実機では未確認([docs/BLUETOOTH.md](docs/BLUETOOTH.md)) |

USBとBluetoothの両方で接続していても大丈夫です。Windowsには同じキーボードが2つ見えますが、
実際に応答する方(両方応答するなら速いUSB)を自動で選びます。

## 開発

アプリは**Tauri 2**で作っています(ウィンドウ・HID・設定はRust、画面はReact)。
開発はWSLで行い、Rustと、Windows向けのビルドに使う道具はコンテナ([.devcontainer/](.devcontainer/))に入っています。
WSLで打ったコマンドは、必要なものだけ自動でコンテナの中で動きます。

```bash
npm install
npm run dev          # 画面だけを開発サーバーで出す(ブラウザで開き、「モックで試す」で触れる)
npm run check        # 型チェック + lint + テスト(コミット時に自動で走る)
npm run check:rust   # Rustの整形・clippy・テスト(src-tauri/を変えたコミットで自動で走る)
npm run deploy:win   # Windows版を作って、Windowsのデスクトップに置く
```
