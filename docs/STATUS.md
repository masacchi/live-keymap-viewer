## 2. HANDOFF から変えたこと・足したこと

| 項目 | HANDOFF | 実際 | 理由 |
|---|---|---|---|
| アンロック | 押すべきキーを示して進める | ロックを見つけたら**自動で開始**。ボタンは無い | 選択肢が 1 つしかない。オーバーレイではボタンが押せない |
| オーバーレイから戻る | ショートカットで | ショートカットに加え、**操作パネル**(移動・濃さ・リサイズ・通常に戻す) | 使ってみての要望 |
| キーマップの変更 | (記述なし) | ウィンドウに戻ると**自動で読み直す**。手動のボタンもある | Vial で編集しながら使うため |
| Vial との同時起動 | (記述なし) | 応答を照合し、他アプリ宛てを捨てる | raw HID の応答は全プロセスに配られる |
| エンコーダー | MVP の対象外 | **割り当てだけ**表示(キーの下に横一列)。回転は表示できない | 回転はプロトコルで観測できない(PROTOCOL.md §6) |
| ビルド | electron-vite | **Vite を直接**使う(設定 3 つ + `scripts/dev.mjs`) | electron-vite の安定版が Vite 8 に対応していなかった(ARCHITECTURE.md §6) |
| 画面(2026-09-22) | (記述なし) | Shift 中は Shift で入る文字を強調、レイヤーの一覧とプレビュー、レイヤー名、オーバーレイの自動フェード、読み込みの進み具合、狭いウィンドウ向けの詰め | 使ってみての要望と、BT で読み込みが数十秒かかることへの備え |
| 配布 | 後回し | インストーラーは無し。`npm run deploy:win` でポータブル一式を置く | wine を使わずに Windows 版を作るため |

## 3. 分かっている制約

- **Bluetooth は未確認。調査と実装計画は [BLUETOOTH.md](BLUETOOTH.md)。** 分かっていること:
  - 実機のファームは RMK v0.8.x で、**USB と BLE のどちらか一方しか動かさない**。USB が出力先の
    あいだ、BT 側の Vial インターフェースは応答しない(2026-09-21 に確認)
  - **BT だけの状態では、OS レベルで Vial が答える**(2026-09-21 実測)。アプリの選択ダイアログには
    「不明なデバイス(E118:0001)」として出る(BT 経由では製品名が取れない)
  - ただし BT の往復は実測 444〜488ms と遅く、**今のアプリはこの遅さで押下がずれる・止まる**
    (再現済み)。BT を使うには BLUETOOTH.md の P2・P3 が要る
- **USB と BT の両方で繋がっていると、同じキーボードの Vial インターフェースが 2 つ見える。**
  VID/PID が同じで見分けが付かず、出力先でない側は何も答えない。以前は先頭を掴んで
  「デバイスが応答しない」になっていた。いまは各候補に `[0xFE, 0x00]` を投げて確かめ、
  答えるもののうち一番速いもの(両方答えるなら USB)を使う([hid/deviceProbe.ts](../src/renderer/src/hid/deviceProbe.ts))。
- **ノブの回転は表示できない。** QMK のエンコーダーは matrix とは別系統で、Vial / VIA にも
  回転を返すコマンドが無い。押し込みは matrix のキーなので光る。
- **Combo / Key Override / One Shot / TT は再現していない**(HANDOFF §3 の対象外)。
- **レイヤー判定は近似。** Permissive Hold などは再現していない。同じ 20ms の間に 2 つ押された
  キーは、行の若い順に押したものとして扱う。
- **Vial コマンド(`0xFE`)の応答は照合できない。** 読み込み中やアンロック中に Vial を操作すると
  取り違える可能性がある。確実なのは Vial を閉じて使うこと。
- **オーバーレイ中はキーマップの自動読み直しが働かない。** フォーカスを取らないため。
  通常ウィンドウに戻すか、戻ってから「キーマップ再読み込み」を押す。
- **定義(物理配置・カスタムキーの名前)はキャッシュしている。** ファームを焼き直したのに図や名前が
  古いままなら「キーマップ再読み込み」を押す(こちらは定義もキャッシュを使わずに読み直す)。
- **TG / DF の状態は、アプリが押下から推測している。** アプリを起動する前や、切れていたあいだに
  押したものは分からない。
- **最小化中の取りこぼし対策(`backgroundThrottling: false`)は Windows で未確認。** WSLg では
  ウィンドウを最小化できず確かめられなかった。最小化 → TG を押す → 戻す、で表示が合っていれば良い。
- 対応は Vial protocol 6 / VIA protocol 9 のみ。

## 4. 今後の候補

きっかけ(いつ手を付けるか)を添えておく。

| 候補 | きっかけ・前提 | メモ |
|---|---|---|
| **Bluetooth 対応** | 次のセッション | [BLUETOOTH.md](BLUETOOTH.md) の P2(選択ダイアログ)→ P3(遅さへの対応)→ P4(抜き差し・切り替えへの追従)→ P5(アンロックの進捗)。P1 は OS レベルまで済み。結果を §1 と README に書く |
| 出力先の切り替え(`SWITCH`)への追従を実機で確かめる | Bluetooth 対応と一緒に | 抜き差し・スリープ復帰での繋ぎ直しは入った(`KeyboardConnection`)。BT への切り替えは P3 が入るまで遅さで失敗するはず。BLUETOOTH.md P4 |
| 本番ビルドに CSP を付ける | いつでも | 起動時に Electron の警告が出ている。xz の展開に WebAssembly を使うので `script-src` に `'wasm-unsafe-eval'` が要る。dev は Vite の都合で緩めたまま、build のときだけ付けるのが良い |
| オーバーレイ中の読み直し | 要望があれば | フォーカスが来ないので、一定間隔で keymap の一部を読んで変化を検出する、など |
| ノブの位置(上 / 下)を設定で選べるようにする | 要望があれば | `KeyboardView` の `encoderPlacement` は既に `'top'` に対応している |
| アイコン・インストーラー・署名 | 配布するとき | electron-builder を入れる。Linux から作るなら wine、または Windows 上でビルド |
| ノブの回転を光らせる | ファームを触れるなら | ファームに独自の raw HID コマンドを足してエンコーダーのイベントを返させる |
| Combo / Key Override の表示 | 要望があれば | Vial の dynamic entry で読める(`[0xFE, 0x0D, 0x03, idx]` / `[0xFE, 0x0D, 0x05, idx]`) |
| ほかのキーボード | 持っている人がいれば | コードの変更はほぼ不要のはず。DEVELOPMENT.md §6 |
